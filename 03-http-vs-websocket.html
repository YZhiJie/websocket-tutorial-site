第 3 章 WebSocket 与 HTTP 的区别与联系 ​

3.1 联系：WebSocket 站在 HTTP 的肩膀上 ​

  1. 握手复用 HTTP：如第 2 章所示，WebSocket 连接通过标准 HTTP 请求的 Upgrade 机制建立。
  2. 共用端口：ws:// 默认 80 端口，wss:// 默认 443 端口，与 HTTP/HTTPS 完全一致——这意味着它能顺利穿过绝大多数防火墙和代理，不需要开放额外端口。
  3. 复用基础设施：Cookies、TLS 证书、Nginx 反向代理、负载均衡等 HTTP 生态设施都能直接用于 WebSocket。

3.2 区别：两种完全不同的通信模型 ​

维度HTTPWebSocket
通信模式半双工，请求-响应一一对应全双工，双方随时主动发送
连接性质短连接（或 keep-alive 复用，但仍是逐请求）持久长连接，一次握手长期使用
消息边界一个请求对应一个响应流式消息，数量/方向无约束
头部开销每次请求都带完整头部（几百字节）握手后帧头最小仅 2 字节
服务端推送不支持（只能靠轮询/SSE 变通）原生支持
状态保持无状态（靠 Cookie/Session 模拟）有状态（连接本身即会话）
URI schemehttp:// / https://ws:// / wss://
协议层应用层协议基于 TCP 的应用层协议（握手借道 HTTP）

3.3 如何选择？ ​

  • 数据偶尔获取、CRUD 操作、RESTful 资源访问 → HTTP
  • 服务端单向推送、低频通知 → SSE（比 WebSocket 更简单，自动重连内建）
  • 双向高频交互、实时性要求高 → WebSocket

实际项目中两者常共存：HTTP API 负责登录、数据查询，WebSocket 负责实时推送。

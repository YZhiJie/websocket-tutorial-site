第二幕 · 一条连接的诞生 ​

对应主线教程：第 2 章 基本概念与工作原理

四阶段生命周期 ​

  1. 握手请求：客户端发 HTTP GET，带 Connection: Upgrade + Upgrade: websocket
  2. 协议升级：服务端回 101 Switching Protocols，此后同一条 TCP 不再说 HTTP
  3. 双向通信：双方互发文本帧 / 二进制帧 / Ping / Pong
  4. 礼貌关闭：互回 Close 帧（可带状态码与原因），再断 TCP

握手报文（curl 抓包实测） ​

请求关键字段：

头部作用
Sec-WebSocket-Key16 字节随机数 Base64，握手校验用
Sec-WebSocket-Version: 13RFC 6455 唯一版本
Origin来源标识，服务端可据此防 CSWSH

响应的 Sec-WebSocket-Accept = Base64(SHA1(Key + 固定 GUID))，RFC 经典示例 Key dGhlIHNhbXBsZSBub25jZQ== 必产生 s3pPLMBiTxaQ9kYGzzhZRbK+xOo=。

它只证明"对方真的懂 WebSocket"，不是身份认证、不是加密（RFC 6455 §10.8）。

数据帧要点 ​

  • opcode：0x1 文本（必须合法 UTF-8）/ 0x2 二进制 / 0x8 Close / 0x9 Ping / 0xA Pong
  • MASK 位：客户端→服务端的帧必须掩码，防恶意字节流欺骗中间代理；密钥明文在帧头，掩码不等于加密
  • Ping 必须回 Pong 并原样带回载荷——所有库（ws、websockets、浏览器）自动处理

关闭状态码 ​

1000 正常 / 1001 离开 / 1006 异常断开（仅本地哨兵值，永不上线）/ 1008 策略拒绝 / 1011 服务端错误。完整表见主线附录 A。

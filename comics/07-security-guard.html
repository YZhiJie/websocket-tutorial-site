第七幕 · 黑客来敲门 ​

对应主线教程：第 7 章 WebSocket 安全机制（含 7.9 RFC 6455 规范解读） 配套代码：secure-server.js、security-test.js

CSWSH 跨站 WebSocket 劫持 ​

黑客把恶意脚本放进钓鱼网页，受害者一旦访问，浏览器就自动向真网站发起 WebSocket 连接并带上登录 Cookie——而 WebSocket 不受同源策略（CORS）约束。防线在于：浏览器会自动带 Origin 头，校验与拒绝的权力在服务端（RFC 6455 §10.2）。

六道防线（全部实测通过） ​

#防线拦截结果
1Origin 白名单（verifyClient）握手失败 HTTP 401
2Token 鉴权（握手 URL 校验）握手失败 HTTP 401
3maxPayload: 4KB 消息上限自动关闭 1009
4单 IP 最多 3 条连接关闭 1013
5滑动窗口 1s ≤ 5 条消息关闭 1013
6JSON try-catch + text 1~500 字符白名单回 error 不断连

运行 npm run secure-server 与 npm run security-test 可复现：合法回显 ✅、伪造 Origin 401 ✅、坏 token 401 ✅、5KB 大包 1009 ✅、7 条连发 1013 ✅、非法 JSON 回提示 ✅。

三个最常见的认知误区 ​

  1. 掩码 ≠ 加密：掩码密钥明文放在帧头，防的是中间代理被字节流欺骗（§10.3），任何中间人都能解开
  2. 握手成功 ≠ 已登录：Sec-WebSocket-Accept 只证明对方懂协议（§10.8），不是身份认证
  3. 非浏览器客户端不守规矩：curl/脚本能伪造任意 Origin 和头部，Origin 之外必须再做 Token 鉴权（§10.1）

机密性与完整性只能靠 wss（TLS），且 HTTPS 页面不允许连接明文 ws://（混合内容限制）。

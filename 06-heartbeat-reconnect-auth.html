6.1 双层心跳体系 ​

生产环境推荐协议级 + 应用级双层心跳：

层级机制能发现不能发现
协议级 Ping/Pong服务端每 10~30s 发 ping 帧半开 TCP 连接（断网、崩溃）应用层假死（事件循环卡死但内核还在回 pong）
应用级心跳客户端定时发 {type:'ping'} 消息，等待业务回包应用层假死、业务逻辑 hang——

4.5 节已实现协议级心跳。应用级看门狗的完整实现见 examples/node/reconnect-client.js，核心逻辑：

javascript
startWatchdog() {
  this.watchdogTimer = setInterval(() => {
    const silentFor = Date.now() - this.lastMessageAt;
    if (silentFor > WATCHDOG_TIMEOUT) {
      // 超过 8s 没有任何入站数据（含 pong），判定假死，主动断开触发重连
      this.ws.terminate();
      return;
    }
    this.ws.ping();
  }, WATCHDOG_INTERVAL);
}

6.2 指数退避 + Full Jitter 自动重连 ​

不要固定间隔重连——服务端重启后，成千上万客户端在同一时刻重连会形成"惊群"，把刚恢复的服务再次打垮。正确姿势：

javascript
scheduleReconnect() {
  this.attempt += 1;
  // 退避上限 = min(30s, 1s × 2^attempt)：1s → 2s → 4s → 8s → … → 30s 封顶
  const cap = Math.min(MAX_DELAY, BASE_DELAY * 2 ** (this.attempt - 1));
  // full jitter：在 [0, cap] 内随机取值，把重连时刻打散
  const delay = Math.random() * cap;
  this.reconnectTimer = setTimeout(() => this.connect(), delay);
}

三个工程细节（都是真实项目踩过的坑）：

  1. 手动关闭与自动重连互斥：用户点了"退出登录"，代码必须知道这是主动的（设 manualClose = true），不能又自动连回去。
  2. 定时器清理：每次重连前清掉旧的看门狗定时器，否则多个定时器并存会导致重复 ping、重复重连。
  3. error 与 close 的关系：error 事件之后通常紧跟 close，重连逻辑统一放 close 里处理，避免触发两次。

6.3 连接鉴权 ​

WebSocket 握手是 HTTP 请求，鉴权信息有三个常见携带位置：

javascript
// ① URL query（最简单，注意 wss 下才安全，避免日志泄露 token）
new WebSocket('wss://api.example.com/ws?token=xxx')

// ② Cookie（浏览器自动携带，服务端读握手请求的 headers.cookie）

// ③ 子协议字段传 token（Authorization 头无法在浏览器 WebSocket API 设置）
new WebSocket('wss://api.example.com/ws', ['bearer', 'xxx'])

6.4 二进制数据与子协议 ​

  • 二进制：传输图片、音频、Protobuf 等用二进制帧。浏览器端 ws.binaryType = 'arraybuffer'（默认 blob），Node 端 message 直接是 Buffer。
  • 子协议：new WebSocket(url, ['json', 'msgpack']) 让两端协商消息格式，服务端通过 Sec-WebSocket-Protocol 响应头确认。常见公开子协议：MQTT、WAMP、STOMP。
